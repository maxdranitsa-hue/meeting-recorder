# Инструкция для Claude Code

Ты помогаешь пользователю поставить инструмент, который превращает его
видеовстречи в текст. В проекте **три разные программы** — сначала выбери
нужную, они не взаимозаменяемы.

Пользователь скорее всего не программист: он участник интенсива по Claude Code,
а не разработчик. Объясняй по-русски, простыми словами, не показывай ему логи и
код. Все команды выполняй сам — ему говори только то, что он должен нажать или
разрешить своими руками. Если нужно его решение, спрашивай по одному вопросу.

## Определи систему сам

Не спрашивай пользователя, какая у него система и версия — узнай сам:

```bash
# macOS
sw_vers -productVersion
# Windows (PowerShell)
[System.Environment]::OSVersion.Version
```

Дальше выбирай по таблице ниже. Пользователю просто скажи, какую версию
ставишь и почему.

## Если репозиторий не клонируется

Репозиторий **приватный**, доступ выдаётся участникам интенсива поимённо. При
ошибке доступа не пытайся её обойти и не предлагай искать проект в других
местах. Скажи пользователю понятными словами примерно так:

> Репозиторий закрытый, и твоего доступа к нему пока нет. Отправь Максиму свой
> логин на GitHub — он выдаст доступ. Если аккаунта GitHub нет, заведи, это
> бесплатно и займёт минуту.

Перед этим проверь очевидное — возможно, доступ есть, а не хватает авторизации:

```bash
gh auth status          # авторизован ли пользователь
gh auth login           # если нет — проведи его через это
```

Если `gh` не установлен: на macOS `brew install gh`, на Windows
`winget install GitHub.cli`. Клонировать можно и обычным `git clone` — тогда
Git попросит логин и токен, и через `gh` это проще.

## Что установить нельзя

Если система пользователя не подходит ни под один вариант из таблицы — скажи
об этом прямо и не выдумывай обходных путей. Лучше честное «на этой системе не
заработает», чем полдня возни и нерабочий результат.

## Сначала: какую из трёх ставить

| | Где работает | Что делает | Ставится из |
|---|---|---|---|
| **Запись звонков** | macOS 14.2+ | сама пишет встречу и расшифровывает; работает на любых встречах, даже когда пользователь не организатор | корень проекта |
| **Запись встреч для Windows** | Windows 10/11 | то же самое, через WASAPI loopback | папка `windows/` |
| **Транскрибатор встреч** | Windows, macOS, Linux | следит за папкой с записями Zoom; запись делает сам Zoom | папка `watcher/` |

Правило выбора:
- **macOS 14.2+** → «Запись звонков» из корня
- **Windows** → `windows/`. Если захват звука там не заработает — `watcher/`
  как запасной вариант
- **Linux или macOS старее 14.2** → `watcher/`

Не пытайся собрать macOS-версию на Windows: `meeting_tap.swift` — нативный код
Core Audio, а `rumps` существует только под macOS. Windows-аналог уже написан
и лежит в `windows/`, начинай с него.

**Про `windows/` знай главное:** код написан без возможности проверить его на
живой Windows. Логика сведения дорожек и расшифровка проверены, а сам захват
через WASAPI и определение окон — нет. Поэтому **всегда прогоняй проверку
захвата** перед тем, как сказать пользователю «готово», и чини по её выводу.

# Запись звонков (macOS)

## Что сделать

Запусти установщик из папки проекта:

```bash
bash install.sh
```

Он сам проверит систему, поставит недостающее, соберёт и установит приложение
в `~/Applications`. Скрипт задаёт вопросы про установку зависимостей — если
пользователь заранее согласился ставить всё, запускай `bash install.sh -y`.

После успешной установки скажи пользователю ровно три вещи:

1. Запустить приложение: `open "$HOME/Applications/Запись звонков.app"` —
   в строке меню сверху появится иконка 🎙
2. При первом запуске оно попросит **ключ Deepgram** (само откроет страницу
   регистрации; новым аккаунтам дают $200 бесплатно, этого хватает на сотни
   часов) и **папку** для расшифровок
3. При первой записи macOS спросит разрешения — **нужно разрешить все три**:
   микрофон, запись звука с этого компьютера, управление Google Chrome

Предложи добавить приложение в автозапуск: Системные настройки → Основные →
Элементы входа.

## Требования, которые нельзя обойти

- **macOS 14.2+.** Запись звука собеседника работает через Core Audio process
  tap — на более ранних версиях этого механизма в системе нет. Если у
  пользователя версия ниже, скажи прямо: нужно обновить macOS, обходного пути
  нет. Не пытайся заменить захват на что-то другое.
- **Только macOS.** На Windows и Linux не работает и портированию малой кровью
  не поддаётся.
- **Homebrew.** Если его нет — дай ссылку https://brew.sh, но **не устанавливай
  Homebrew сам без явного согласия пользователя**: это большая установка,
  меняющая систему.

## Если что-то пошло не так

Диагностируй по журналу: `~/Library/Logs/meeting-recorder.log`

| Симптом | Причина и что делать |
|---|---|
| `Помощник записи завершился до старта` | Не выдано разрешение «Запись звука с этого компьютера». Системные настройки → Конфиденциальность и безопасность → Запись звука. Включить для «Запись звонков» |
| Пишется только голос пользователя, собеседника нет | То же разрешение. Плюс в Zoom: Настройки → Звук → Динамик = «Как в системе» |
| `Deepgram отклонил ключ (HTTP 401)` | Неверный ключ. Меню приложения → «Изменить ключ Deepgram…» |
| `HTTP 402` | На аккаунте Deepgram закончились деньги |
| Meet и Телемост не определяются, Zoom работает | Нет разрешения на управление Chrome. Системные настройки → Конфиденциальность → Автоматизация |
| Иконка 🎙 не появилась | Смотри `/tmp/meetingrec-build.log`. Чаще всего — старый Python; установщик должен был взять 3.11+ из brew |
| Приложение перестало работать после переноса папки | Собрано в режиме alias. Верни папку на место или запусти `bash install.sh` заново |

Пересборка после правок в коде: `bash install.sh` ещё раз — он корректно
заменит установленную версию.

## Границы

Настройки живут в `~/Library/Application Support/MeetingRecorder/config.json`.
Там же лежит ключ Deepgram — **никогда не показывай его содержимое в чате и не
копируй в другие файлы.**

Не коммить в репозиторий: `config.json`, `.venv/`, `build/`, `dist/`,
собранный бинарник `meeting_tap`, любые записи и расшифровки.

Приложение записывает обе стороны разговора. Если пользователь спрашивает, как
скрыть запись от собеседника или как записывать незаметно — не помогай с этим:
предупреждение участников во многих странах обязательно по закону.

## Как всё устроено (если понадобится править)

| Файл | За что отвечает |
|---|---|
| `meeting_tap.swift` | Нативный захват: копия системного звука + микрофон в один WAV 16 кГц. Выход пользователя не трогает — наушники и громкость работают как обычно |
| `meeting_recorder.py` | Детект встречи (Zoom — процесс `CptHost`; Meet и Телемост — вкладка Chrome), запуск и остановка записи, расшифровка |
| `transcription.py` | Deepgram nova-3 с разделением по говорящим. Только stdlib — внутри бандла нет pip-зависимостей |
| `naming.py` | Имя файла. Если установлен Claude Code — берёт короткую тему из разговора, иначе имя по дате и длительности |
| `menubar_app.py` | Иконка в строке меню, первый запуск, настройки |
| `config.py` | Настройки пользователя, проверка версии macOS |
| `install.sh` | Всё вышеперечисленное собирает и ставит |

Ключевое архитектурное решение: захват идёт через **process tap**, а не через
виртуальное аудиоустройство вроде BlackHole. Раньше была схема с BlackHole и
подменой устройства вывода — она ломала звук у пользователя: на старте записи
перехватывался выход, отваливались наушники, иногда собеседник вообще не
попадал в запись. Process tap снимает копию микса и ничего не переключает.
**Не возвращай схему с виртуальным устройством.**

Из этого следует ответ на частый вопрос: **в наушниках всё пишется, настраивать
ничего не надо.** Тап снимает копию системного микса до того, как звук уходит
на устройство вывода, поэтому наушники, колонки и Bluetooth равнозначны, и их
можно переключать посреди встречи.

# Транскрибатор встреч (Windows, macOS, Linux)

Лежит в папке `watcher/`. Следит за папкой с записями и расшифровывает новые
файлы. Записи делает Zoom — программа только подхватывает готовое.

## Что сделать

```bash
cd watcher
python setup_watcher.py
```

Скрипт сам спросит ключ Deepgram, папку с записями, папку для расшифровок и
настроит автозапуск. Помоги пользователю с ответами, дальше объясни:

1. В Zoom → Настройки → **Запись** проверить путь сохранения — он должен
   совпадать с тем, что указали программе
2. Там же включить **«Записывать отдельный аудиофайл»** — расшифровка выйдет
   быстрее и дешевле, чем из видео
3. Zoom → Настройки → Общие → автоматическая запись при старте встречи, если
   хочет полный автомат

Скажи про ограничение прямо: **записывать встречу в Zoom может организатор или
тот, кому организатор разрешил.** На своих встречах пользователь организатор —
там работает. На чужих запись зависит от хоста, и это правило Zoom, а не
недоработка программы.

Проверь, что установлен Python 3.9+. На Windows при установке нужна галочка
**Add Python to PATH**. Если нет `ffmpeg` — предложи `winget install ffmpeg`
(Windows) или `brew install ffmpeg` (macOS); без него видео уходит на
расшифровку целиком и это заметно дольше.

## Если что-то не так

Журнал: `%APPDATA%\MeetingTranscriber\transcriber.log` (Windows) или
`~/Library/Application Support/MeetingTranscriber/transcriber.log` (macOS).

| Симптом | Причина |
|---|---|
| Ничего не расшифровывается | Путь слежения не совпадает с папкой записей Zoom, либо Zoom вообще не пишет встречу |
| Старые записи проигнорированы | Так задумано: при первом запуске архив помечается обработанным, иначе пользователь получит счёт за все прошлые записи. Чтобы взять старое — удалить `processed.json` рядом с настройками |
| `Deepgram отклонил ключ` | Неверный ключ или кончились средства. Перезапустить `setup_watcher.py` |
| Файл больше 2 ГБ | Предел Deepgram. Включить в Zoom отдельный аудиофайл |
| Расшифровался и mp4, и audio_only | Не должно происходить: на папку берётся один файл. Если случилось — смотри `collect_candidates()` в `watcher.py` |

## Устройство

| Файл | За что отвечает |
|---|---|
| `watcher.py` | Обход папок, выбор файлов, извлечение звука, расшифровка, именование |
| `setup_watcher.py` | Первичная настройка и автозапуск под три системы |
| `config.py` | Настройки и список уже обработанных файлов |
| `transcription.py` | Deepgram — копия корневого модуля, чтобы папку можно было забрать отдельно |

`transcription.py` намеренно продублирован: `watcher/` должен работать, даже
если пользователь скачал только его. Правишь расшифровку — правь обе копии.

# Запись встреч для Windows (папка `windows/`)

Полный аналог macOS-версии: сама замечает встречу, пишет обе стороны, ничего
не требует от Zoom. Работает на чужих встречах.

## Что сделать

```
cd windows
python setup_windows.py
```

Установщик ставит библиотеки (`PyAudioWPatch`, `pystray`, `Pillow`), проверяет
`ffmpeg`, спрашивает ключ и папку, прогоняет проверку захвата и настраивает
автозапуск.

**Проверку захвата не пропускай** — пять секунд, и сразу видно правду:

```
python audio_capture.py --test
```

Она отдельно скажет про каждую сторону: «звук есть» или «тишина». Пока обе
стороны не дают звук, говорить пользователю «готово» нельзя.

## Как чинить

| Что показала проверка | Причина |
|---|---|
| собеседник: тишина | Звук идёт не через обычное устройство Windows. Проверь устройство вывода по умолчанию; в Zoom → Настройки → Звук поставь системное устройство |
| микрофон: тишина | Параметры → Конфиденциальность → Микрофон → разрешить доступ классическим приложениям |
| `Не найдено устройство WASAPI loopback` | Редкий случай: нестандартный аудиодрайвер. Посмотри список устройств через `pyaudiowpatch` и подбери loopback вручную |
| `Не найден ffmpeg` | `winget install ffmpeg`, затем перезапустить консоль |

Встреча не определяется — покажи вывод:

```
python meeting_detect.py --list
```

Команда печатает все окна с заголовками и классами и отмечает те, что считает
встречей. Признаки заданы в начале `meeting_detect.py` — если у пользователя
Zoom другой версии или локализации, добавь его класс или заголовок туда. Это
самое вероятное место поломки, потому что заголовки зависят от языка.

## Устройство

| Файл | За что отвечает |
|---|---|
| `audio_capture.py` | WASAPI loopback + микрофон в два WAV, сведение через ffmpeg, самопроверка |
| `meeting_detect.py` | Определение встречи по окнам и процессам, только ctypes без pywin32 |
| `recorder.py` | Цикл: заметил встречу → записал → расшифровал → сохранил |
| `tray_app.py` | Иконка рядом с часами |
| `setup_windows.py` | Установка целиком |

Настройки и расшифровка берутся из `../watcher/` — папку `windows/` нельзя
скачать отдельно, нужен весь репозиторий.

**Почему две дорожки сводятся через ffmpeg, а не в Python:** у микрофона и у
колонок разная частота дискретизации и свой дрейф, а `audioop` из стандартной
библиотеки удалён в Python 3.13. ffmpeg делает и ресемплинг, и микс. В фильтре
стоит `normalize=0` намеренно: со стандартной нормализацией громкость делится
на число входов и тихая сторона разговора становится неразличимой.

**Возможное улучшение, если понадобится идеальное разделение сторон:** писать
не моно, а стерео — микрофон в левый канал, собеседника в правый (`join` вместо
`amix`) — и звать Deepgram с `multichannel=true`. Тогда «я» и «собеседник»
разделяются точно, без опоры на диаризацию. Сейчас сделано моно с диаризацией —
так же, как в проверенной временем macOS-версии.
